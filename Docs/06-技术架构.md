# 06 技术架构

> 状态：`首版` 架构；联机仅预留 ｜ 关联：[02-战斗与兵种](02-战斗与兵种.md)、[04-关卡与模式](04-关卡与模式.md)、[08-待办清单](08-待办清单.md)
> TL;DR：Godot 4.x + GDScript。纯逻辑模拟层（固定 20Hz、种子随机、数据驱动）与节点表现层分离。首版不写联机，但所有战斗指令走命令层。

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | Godot 4.x（锁定当前稳定 minor 版本） | 2D 管线成熟、开源、单人友好 |
| 语言 | GDScript | 开发快；本项目单位数 < 100，性能足够 |
| 渲染 | 2D，640x360 逻辑分辨率，整数放大 | 像素风；见 [05](05-美术音频UI.md) |
| 物理 | 不使用 Godot 物理引擎 | 1D 战斗，自写移动/索敌，确定性更好 |
| 数据 | JSON + 启动时校验 | 策划可读可改；避免 .tres 合并冲突 |
| 存档 | `user://save.json`，原子写入 | 简单、可迁移 |
| 测试 | GUT（Godot Unit Test）或 gdUnit4 | 模拟层可脱离场景测试 |
| 版本控制 | Git + `.gitignore`；美术/音频可 LFS | 单人也要能回滚 |

> 不选 C#：首版没有性能瓶颈，GDScript 迭代更快。若后期模拟层性能不足，再只替换热点。

## 分层

```text
┌────────────────────────────────────────────┐
│ 表现层 View（Godot 节点）                   │
│ 单位/投射物/建筑视图、镜头、小地图、HUD、VFX │
│ 只读快照，不修改战斗状态                     │
└───────────────────▲────────────────────────┘
                    │ snapshot（每 tick）
┌───────────────────┴────────────────────────┐
│ 模拟层 Sim（纯 GDScript，RefCounted）       │
│ 单位、投射物、经济、建筑、波次、战斗结算     │
│ 固定 20Hz，种子随机，无 Node/SceneTree 依赖 │
└───────────────────▲────────────────────────┘
                    │ command（出兵/移动/建造）
┌───────────────────┴────────────────────────┐
│ 输入/UI 层（Godot 节点）                    │
│ 鼠标/键盘 -> Command -> queue               │
└────────────────────────────────────────────┘
```

**硬规则**：

- 模拟层不得 `get_node()`、不得访问 `SceneTree`、不得用全局 `randi()`/`randf()`。
- 表现层不得直接改单位 HP/金币/位置；所有改变通过 Command。
- 模拟层每 tick 产出只读快照；表现层按 entity_id 同步视图。
- 界面按钮的可用状态可以读快照，但点击必须生成 Command，由模拟层校验后执行。

## 核心类

| 类 | 职责 | 关键 API |
|---|---|---|
| `BattleSim` | 持有全部战斗状态；固定 tick；应用命令；产出快照 | `_init(seed, level_def)`, `queue_command(cmd)`, `tick()`, `snapshot()`, `is_finished()` |
| `SimUnit` | 单位状态：id、兵种、阵营、路、x、hp、状态、冷却、目标 | `step(delta)`, `take_damage(amount, source)` |
| `SimProjectile` | 追踪目标、命中结算 | `step(delta)` |
| `MovementSystem` | 推进线/移动/HOLD/索敌移动 | `update(units, delta)` |
| `CombatSystem` | 索敌、攻击间隔、伤害公式、死亡/奖励 | `update(units, projectiles, delta)` |
| `EconomySystem` | 金币收入、花费、人口 | `add_gold`, `can_afford`, `spend`, `pop_used` |
| `BuildingSystem` | 槽位、建造、升级、效果 | `build(slot, type)`, `upgrade(slot)` |
| `WaveSystem` | 固定波次/无尽预算、生成敌军 | `update(tick)`, `spawn_wave()` |
| `BattleView` | 订阅快照，增删/更新视图 | `apply_snapshot(snapshot, alpha)` |
| `CameraRig` | 切路、平移、跟随 | `focus_lane(id)`, `pan(delta)` |
| `Minimap` | 绘制两路态势、点击切路 | `update(snapshot)` |
| `HUD` | 金币/人口/血量/波次/出兵卡/冷却 | `update(snapshot)` |
| `GameState` | 解锁、星级、设置、无尽最高分 | `unlock_level`, `record_stars`, `save` |

## 固定 tick 与快照

- 模拟频率：**20 Hz**（`delta = 0.05s`）。
- `SimRunner`（Node）在 `_physics_process` 或累加器里固定步进；表现层在 `_process` 用插值。
- 每个 tick：
  1. 应用命令队列（按到达顺序）。
  2. 经济/建筑/波次更新。
  3. 移动/索敌/攻击/投射物/死亡。
  4. 生成快照（复用数组，减少分配）。
- 快照字段（示例）：

```text
tick: int
gold: int
income_per_sec: float
pop_used: int
pop_max: int
base_hp: int
wave_index: int
wave_timer: float
units: [{id, def_id, team, lane, x, hp, max_hp, state, selected}]
projectiles: [{id, type, x, y, target_id}]
buildings: [{slot, type, level}]
advance_lines: [x_lane_0, x_lane_1]
finished: {result: "win"|"lose"|null}
```

- 表现层用 `entity_id -> view` 字典；新 id 创建，消失 id 播放死亡/销毁，位置用前后快照插值。

## 命令层

所有玩家操作变成 Command，由模拟层校验：

| Command | 字段 | 校验 |
|---|---|---|
| `spawn_unit` | `unit_def_id`, `lane` | 金币、人口、冷却、关卡解锁 |
| `set_advance_line` | `lane`, `x` | 在己方可达范围 |
| `move_squad` | `unit_ids[]`, `x`, `lane` | 单位存活、同路、己方 |
| `hold_squad` | `unit_ids[]` | 存活、己方 |
| `return_squad` | `unit_ids[]` | 存活、己方 |
| `build` | `slot`, `building_type` | 槽位空、金币、已解锁 |
| `upgrade` | `slot` | 已建造、未满级、金币 |
| `pause` | `bool` | 仅表现层/游戏循环，不进模拟 |

- 命令失败返回原因（金币不足/人口满/冷却中），UI 显示 toast，不静默失败。
- 命令队列按 tick 应用；同一 tick 内多命令按顺序。
- 后期微操/英雄/魔法只需新增 Command 类型，不改表现层输入主流程。

### `data/units.json`

```json
{
  "swordsman": {
    "name_key": "unit.swordsman",
    "cost": 30,
    "pop": 1,
    "hp": 180,
    "damage": 18,
    "attack_interval": 1.0,
    "range": 24,
    "speed": 55,
    "attack_type": "melee",
    "armor_type": "heavy",
    "passive": "shield_wall",
    "unlock_level": 1
  }
}
```

### `data/levels/level_01.json`

```json
{
  "id": 1,
  "name_key": "level.01",
  "base_hp": 20,
  "star_thresholds": [12, 18],
  "available_units": ["swordsman", "archer"],
  "available_buildings": ["farm_a"],
  "unlock_on_clear": ["level_02", "spearman", "barracks_top"],
  "waves": [
    {"time": 20, "lane": 0, "spawns": [{"unit": "swordsman", "count": 3}]},
    {"time": 70, "lane": 0, "spawns": [{"unit": "swordsman", "count": 5}]}
  ]
}
```

- 启动时校验：必填字段、兵种 ID 存在、波次时间递增、星级阈值合法。
- 数据错误直接报错并列出文件/字段，不静默使用默认值。
- 热重载可选（开发期），发布版关闭。

## 确定性

首版单机不要求跨平台完全确定性，但为联机预留：

- 固定 tick，不用 `delta` 直接驱动战斗。
- 所有随机走 `RNG`（种子），不用全局随机。
- 单位迭代按 `entity_id` 升序，不按字典/节点顺序。
- 不使用 Godot 物理/导航。
- 浮点位置可能跨平台有差异；未来联机若需严格确定性，改用定点数或锁步校验，不在首版实现。
- 命令日志 + 种子可回放单机战斗，用于复现 bug（`后期` P1）。

## 场景树

```text
BattleScene (Node2D)
├── SimRunner (Node)          # 持有 BattleSim，固定 tick
├── World (Node2D)
│   ├── Background
│   ├── Lane0
│   ├── Lane1
│   ├── Units (Node2D)        # UnitView 容器
│   ├── Projectiles (Node2D)
│   └── VFX
├── CameraRig (Camera2D)
└── UI (CanvasLayer)
    ├── HUD
    ├── Minimap
    ├── BuildingPanel
    └── ResultScreen
```

- `SimRunner` 只负责 tick 与快照；不渲染。
- `BattleView` 可与 `World` 合并为场景脚本；保持职责分离即可。
- UI 通过 `GameState`/`SimRunner` 发命令；不直接找单位节点。

## 存档

- 路径：`user://save.json`。
- 结构见 [04](04-关卡与模式.md)；加载时校验 `version`。
- 原子写入：写 `save.tmp` -> `DirAccess.rename` 替换；失败保留旧档。
- 设置单独或同档；首版同档。
- 不做云存档（`远期`）。
- 存档损坏：提示并提供“重置进度”按钮，不自动覆盖。

## 测试

| 层级 | 内容 | 工具 |
|---|---|---|
| 模拟单元测试 | 伤害公式、克制、被动、经济、人口、波次预算 | GUT/gdUnit4 |
| 场景测试 | 出兵/建造/移动命令成功与失败路径 | GUT + 无头场景 |
| 回放测试 | 固定种子 + 命令序列 -> 预期结果 | 自定义脚本 |
| 手动测试 | 5 关 + 无尽，手柄/键鼠（首版键鼠） | 人工 |

最低要求：克制矩阵、经济花费、波次生成、存档往返各有测试；每次改数值跑一遍。

## 性能预算

| 项 | 目标 |
|---|---|
| 帧率 | 60 FPS（1080p，普通笔记本） |
| 同屏单位 | < 100（含双方） |
| 模拟 tick | < 2 ms |
| 渲染 | < 8 ms |
| 内存 | < 500 MB |
| 加载关卡 | < 1 秒 |

优化顺序：减少每 tick 分配 -> 对象池（投射物/视图） -> 批量更新 -> 最后才考虑 C#。

## 联机预留（`远期`）

- 已有：模拟/表现分离、命令层、种子随机、固定 tick、实体 ID。
- 未来合作 PvE：主机跑模拟，客户端发命令 + 收快照（状态同步），比锁步更稳。
- 未来 PvP：需要严格确定性或服务器权威；浮点差异要处理（定点/容差校验）。
- 首版不写网络代码、不引入 ENet、不做大厅。
- 任何“为联机提前优化”的改动，若不影响单机可测性，才允许进入首版。

## 工程与发布

- `git init`；`.gitignore` 排除 `.godot/`、`export/`、`*.tmp`。
- 分支：`main` 可玩；功能分支短命；单人也要提交信息清晰。
- 导出：Windows Desktop（x86_64），itch.io butler 上传；版本号 `0.x.y`。
- 构建 checklist：无报错、无缺失资源、存档路径可写、窗口缩放正确、退出干净。
- 崩溃日志：Godot 自带 log；发布版保留 `user://logs/`。

## Open Questions

- 20Hz 是否足够？投射物速度 200-300 px/s，插值后应可接受；M1 验证。
- JSON 还是自定义 Resource？JSON 易改但无编辑器提示；首版 JSON。
- 是否需要回放？若 bug 复现困难，M4 加命令日志。
- 单位视图用 `AnimatedSprite2D` 还是 `AnimationPlayer`？按动画师习惯定。
- 是否使用 TileMapLayer 做地面？首版可用简单 Sprite 拼接，减少学习成本。
