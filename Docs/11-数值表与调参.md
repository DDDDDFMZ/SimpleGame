## 数值文件

| 文件 | 内容 |
|---|---|
| `data/units.json` | 8 职业全部数值、中文名、碰撞箱、站位顺序 |
| `data/guilds.json` | 三协会名称/定位/解锁、T0-T3 tiers（cost/cap/rank_gate） |
| `data/balance.json` | 经济/声望/人情/星级/无尽/容量/站位/支援全局数值 |
| `data/counters.json` | 攻型 × 甲型克制矩阵 |
| `data/campaign.json` | 委托/无尽路径、协会解锁 |
| `data/levels/*.json` | 波次/简报/地图引用；波次优先 `route` |
| `data/maps/*.json` | v2 节点图（nodes/edges/spawns） |

## units.json

顶层对象 key = 单位 id，例如：

```json
{
  "swordsman": {
    "display_name": "Swordsman",
    "display_name_cn": "剑士",
    "guild": "iron",
    "relation_tier": 0,
    "role": "vanguard",
    "cost": 30,
    "pop": 1,
    "hp": 180,
    "damage": 18,
    "attack_interval": 1.0,
    "range": 24,
    "speed": 55,
    "attack_type": "melee",
    "armor_type": "heavy",
    "passive": "shield_wall",
    "body_width": 12,
    "body_height": 18,
    "station_rank": 0,
    "sort_order": 0
  }
}
```

- `display_name_cn` 游戏内中文名；改英文名不改中文显示。
- `body_width/body_height` 碰撞箱，同时用于横向槽位/选中/渲染；美术换图不改玩法。
- `station_rank` 默认前后站位；`sort_order` 卡牌顺序。
- `relation_tier` 0-3，对应协会 tiers。
- 新增职业：加 key、guild、relation_tier、sort_order、station_rank，并运行 validator。

## guilds.json

```json
{
  "iron": {
    "name": "Iron Oath",
    "name_cn": "铁誓会",
    "short": "IRON",
    "short_cn": "铁誓",
    "identity_cn": "前排与重甲",
    "unlock_after": 0,
    "sort_order": 0,
    "tiers": [
      {"cost": 30, "cap": 1, "rank_gate": 0},
      {"cost": 60, "cap": 2, "rank_gate": 0},
      {"cost": 110, "cap": 2, "rank_gate": 1},
      {"cost": 160, "cap": 1, "rank_gate": 2}
    ]
  }
}
```

- `tiers` 顺序即 T0-T3；`rank_gate` 是所需声望 Rank。
- 职业解锁由 units 的 `guild + relation_tier` 推导，**不要**再写 `tiers[].units`。
- `unlock_after` 与 `campaign.json` 的协会解锁应一致。

## balance.json / counters.json

`balance.json` 是扁平键：

```json
{
  "base_pop": 8,
  "promo_kills": [1, 3, 5],
  "promo_cost": [40, 80, 120],
  "road_slot_width": 12,
  "road_slot_padding": 1,
  "squad_spacing": 16,
  "squad_slot_tolerance": 3,
  "squad_regroup_distance": 80,
  "assist_radius": 150,
  "vision_radius": 180
}
```

- 数组用 `[1, 3, 5]`，不要写 `1|3|5`。
- `road_slot_width/padding` 决定每条边横向碰撞槽位；`squad_*`/`assist_*` 决定编队与支援。
- `counters.json`：`{"melee": {"light": 1.5, "heavy": 0.75}, ...}`。

## 地图/关卡

- 地图 schema/编辑器见 [12](12-地图格式与编辑器.md)。
- 波次用稳定出生口 id：`"route": "enemy_north"`；旧 `lane` 仍兼容但会受 spawn 顺序影响。
- 手改：改 JSON → 重启 → validator；图形：调试版 F3 / `--map-editor`。
- 当前 C1/C2 用 `greyhaven_road.json`，C3/无尽用 `mistmarsh_road.json`；C3 起始金币 210。

## 设置

- 个性化设置唯一路径：`user://settings.json`（Windows 常见为 `%APPDATA%\Godot\app_userdata\SimpleGame\settings.json`）。
- 游戏内：关卡选择 `O`，或暂停菜单“设置”。
- 可改：默认镜头缩放、窗口缩放/全屏、站位顺序；恢复默认。
- 旧 `save.json.settings` 首次启动自动迁移；进度存档升 v4 后不再写设置。

## 校验/测试

```bash
"D:/Godot_v4.7/Godot_v4.7-stable_win64.exe" --headless --path . --script tools/validate_data.gd
"D:/Godot_v4.7/Godot_v4.7-stable_win64.exe" --headless --path . --script tests/test_data.gd
"D:/Godot_v4.7/Godot_v4.7-stable_win64.exe" --headless --path . --script tests/test_settings.gd
"D:/Godot_v4.7/Godot_v4.7-stable_win64.exe" --headless --path . --script tests/test_m7_squad.gd
```

- JSON 不允许注释/尾逗号；UTF-8；小数用 `.`。
- units 必填：`display_name_cn/guild/relation_tier/role/cost/pop/hp/damage/attack_interval/range/speed/attack_type/armor_type/body_width/body_height/station_rank/sort_order`；guilds 必填名称/定位/解锁/排序/tiers；tier 必填 `cost/cap/rank_gate`。
- 缺失必填键、未知 balance 键、类型错误（如把 `base_pop` 写成字符串）都会让 validator 非 0；新增 balance 键需同步 `game_data.gd` 的 `KNOWN_BALANCE`/类型表。
- 改完需重启游戏；当前无热重载。
- 出口：`DATA VALID: units=8 guilds=3 maps=2 levels=3`。
