旧 `data/units.json`、`data/guilds.json` 已不再加载；改它们不会生效。

## 编辑规则

- UTF-8 **无 BOM**；逗号分隔；小数用 `.`（不要 `,`）。
- 不要改表头/列名；不要插入空列；一行一个单位/协会层级。
- 布尔写 `true/false`。
- `sort_order` 控制 UI 顺序；同值按 id。
- `notes` 可留空；不会进游戏。
- 改完运行验证：

```bash
"D:/Godot_v4.7/Godot_v4.7-stable_win64.exe" --headless --path . --script tools/validate_data.gd
```

- 验证失败会打印 `文件:行: 原因`；修好再启动。
- 游戏启动读取一次；改完需重启。热重载 F9 为后续项。

## units.csv 列

`id,name_key,display_name,guild,relation_tier,role,recruitable,cost,pop,hp,damage,attack_interval,range,speed,attack_type,armor_type,passive,projectile_speed,cooldown,heal_amount,heal_interval,heal_range,sort_order,notes`

- `guild`：`iron/verdant/arcane`。
- `relation_tier`：0-3，对应协会层级；解锁需 `guild_tier >= relation_tier`。
- `role`：`vanguard/anti_armor/shock/ranged/flanker/siege/aoe/support`。
- `attack_type`：`melee/ranged/siege`；`armor_type`：`light/heavy`。
- `passive`：`shield_wall/armor_pierce/volley/charge/splash/siege_master/backstab/heal`。
- `heal_*` 只对 `heal` 被动生效。

## guild_tiers.csv 列

`guild_id,tier,cost,cap,rank_gate,notes`

- `tier` 0-3；`cap` 加到招募上限。
- `rank_gate`：晋升到该层所需声望 Rank（0/1/2）。
- 单位由 `units.csv` 的 `guild+relation_tier` 自动推导，不在 guilds 表里重复写。

## 调参原则

1. 先改一个杠杆（数量/成本/HP/收入），不要同时改 5 个。
2. 用 C3 自动试玩 + 真人试玩双指标；自动脚本只是下限，不是玩家体验。
3. 信息层（波次预览/角色图标/提示）先于数值；不要让“看不见”被误判成“难”。
4. 每次调参记录：改了什么、为什么、自动结果、真人结果。
